# Лендинг luum.space

**Дата:** 2026-04-24
**Статус:** дизайн утверждён, к плану

## Контекст

Сейчас `luum.space` — это сразу логин-страница. Клуб планирует масштабироваться с текущих 3 до 8–10 участников, и нужна поверхность, которая описывает мастермайнд и «продаёт» его потенциальному участнику до момента подачи заявки.

Продукт одновременно — **закрытый мужской клуб, где можно снять маску гендиректора**, и **серьёзный движок под капотом** (LUMM: 12-недельные цели, LLM-анализ отчётов, финансы в ленте, банк/штрафы, штурвал, smart-напоминания). Лендинг должен передать обе стороны: тёплое братство и инженерную дисциплину.

Регистрации как пользовательского флоу не существует — участники проходят через приглашение/отбор. Поэтому лендинг не ведёт к формам регистрации, а содержит только CTA «оставить заявку» (контактный) и маленькую ссылку `войти` для уже участников.

## Цель

На `luum.space` отдать публичный маркетинговый лендинг. Вход для действующих участников переезжает на `luum.space/login` (сейчас живёт на `/login` внутри route-group `(auth)` — URL не меняется, меняется только корневой маршрут `/`).

## Решения

| Вопрос | Выбор |
|---|---|
| Позиционирование | Гибрид «закрытый клуб» + «серьёзный инструмент». Доминанта — exclusivity, инструмент — подпорка. |
| Тон | Мужской, сдержанный, без продажной интонации. Можно жёстко, нельзя пошло. |
| Структура | Трёхактная: Акт I «Как мы живём» → Акт II «Что под капотом» → Акт III «Вход». Сам формат отражает философию клуба. |
| Регистрация | CTA «Оставить заявку» (почта/телеграм-контакт), **никакой кнопки «Регистрация»**. Для действующих участников — маленькая ссылка `войти` в hero и footer. |
| URL-маршрутизация | `/` = лендинг (новый публичный). Текущий `/` держит Dashboard (`src/app/(main)/page.tsx`) — **переезжает на `/dashboard`**. После логина редирект `/login → /dashboard` (сейчас редиректит на `/`). `/login` как URL — без изменений. Остальные маршруты (`/members`, `/calendar`, …) — не трогаем. |
| Защита лендинга | Публичен для всех. В `src/proxy.ts` явно добавить `/` в публичный allowlist. |
| Палитра | LUMM-dark + gold (как весь остальной софт). Не editorial-стиль мастера. Тёмное, сдержанное, с акцентами золотом. |
| Скриншоты интерфейса | Реальные. Не моковые. Сделать через тестовые данные на отдельной учётке — чтобы не светить реальные имена/цифры. Хранить в `public/landing/`. |
| Контент-источник | Констатация из `/constitution` переиспользуется. Ценности, формат встреч, штрафы — не переписываем, ссылаемся на один источник правды (позже — можно извлечь в общие компоненты/данные). |
| Где взять место для CTA «Оставить заявку» | Контакт — ссылка на телеграм админа (env: `NEXT_PUBLIC_APPLICATION_CONTACT`, значение из настроек). Форму с БД не делаем в MVP. |
| «Окно приёма» — откуда берём свободные места | Хардкод в конфиге/env (`NEXT_PUBLIC_OPEN_SLOTS`, `NEXT_PUBLIC_NEXT_WINDOW_DATE`). Автоматика по БД — позже. |
| Отзывы участников | Опционально. Если вставляем — инициалы/ники без фото, с разрешения каждого. В MVP — пропускаем, не хватает материала. |
| SEO / OG | Базовый `<title>`, `<meta description>`, og-image. Без sitemap и индексации в MVP. |
| i18n | Только русский. |
| Responsive | Мобильная версия — обязательна. Tailwind-брейкпоинты как в остальном приложении. |

## Скоуп

**Делаем:**
- Корневой маршрут `/` — публичный лендинг в новой route-group `(marketing)` (не внутри `(main)` и не `(auth)`), чтобы не наследовать ни сайдбар, ни auth-layout.
- Обновить `src/proxy.ts`: добавить `/` в публичный allowlist.
- Набор блоков по трёхактной структуре — см. раздел «Структура лендинга» ниже.
- `src/lib/landing.ts` — чистые helpers (парсинг даты окна, плюрализация «свободных мест»). Юнит-тесты.
- Переиспользуемые компоненты-блоки в `src/components/landing/` (по блоку на файл: `HeroBlock.tsx`, `MirrorBlock.tsx`, …) — так проще итерировать по одной секции без перестройки соседей.
- Скриншоты в `public/landing/`: мастер цели, лента `/financials`, карточка анализа отчёта, карточка светофора, пример сообщения бота в telegram.
- Базовое SEO в `generateMetadata` для `/`.
- Env-переменные: `NEXT_PUBLIC_APPLICATION_CONTACT` (ссылка на ТГ админа), `NEXT_PUBLIC_OPEN_SLOTS` (число), `NEXT_PUBLIC_NEXT_WINDOW_DATE` (ISO-дата). Дефолты в коде — безопасные заглушки, без крашей если не заданы.

**Не делаем:**
- Форма заявки с отправкой на бэк / в БД. CTA уводит в Telegram.
- Многоязычность.
- Автоматическое определение свободных мест по БД (публично отдавать статистику группы — не хочется).
- A/B-тестирование, аналитику, пиксели.
- Отзывы с фотографиями.
- Кнопка/флоу регистрации. Самостоятельно завести аккаунт нельзя — только через `/invite/<token>` от админа (существующий флоу).
- Блог / отдельные страницы «Конституция публично», «О клубе детальнее». Только главный `/`.
- Анимации-наркомания. Парочка аккуратных акцентов (переливающаяся CTA — уже есть `.btn-shimmer`), остальное — статика.

## Архитектура

### Маршруты и layouts

Текущее дерево (проверено):

```
src/app/
  (auth)/
    login/page.tsx
    invite/[token]/page.tsx
  (main)/
    layout.tsx       -- сайдбар + UserMenu
    page.tsx         -- сейчас = /  (Dashboard)
    DashboardClient.tsx
    ...
  (goal-wizard)/
    goal/new/page.tsx
  layout.tsx
```

Что меняется:

1. Создаём `(marketing)/layout.tsx` (минимальный: свой header с лого и ссылкой `войти`, footer) и `(marketing)/page.tsx` (корневой `/`, собирается из блоков).
2. Переносим текущий `(main)/page.tsx` и `(main)/DashboardClient.tsx` в `(main)/dashboard/page.tsx` + `(main)/dashboard/DashboardClient.tsx`. URL становится `/dashboard`.
3. После успешного логина — редирект на `/dashboard` вместо `/`. Найти место редиректа в `src/app/api/auth/login` (или как называется роут) и изменить.
4. Навигация в сайдбаре: пункт, который сейчас ведёт на `/` как dashboard, — обновить на `/dashboard`. Проверить все остальные ссылки в приложении на `href="/"` — их быть не должно после миграции.
5. В `src/proxy.ts` — `publicPaths` расширяется: к текущим `["/login", "/invite", "/api/auth"]` добавляется точное совпадение `pathname === "/"`. Сейчас proxy для незалогиненного на `/` редиректит на `/login` — после изменения незалогиненный остаётся на лендинге.

### Защита

В `src/proxy.ts` добавить `/` в публичные пути. Всё остальное поведение (защита `/admin/*`, `(main)` требуют auth, `/login` публичен) — без изменений.

### Контент-источники

Текст конституции дублировать **нельзя** — это один источник правды. На MVP допустимо руками переписать ключевые куски в лендинг с немного более продающей интонацией, но на будущее стоит извлечь константы (ценности, штрафы, формат встречи) в `src/content/constitution.ts` и тянуть их и в `/constitution`, и в лендинг. В MVP — инлайним, помечаем TODO в коде.

### Структура лендинга (блоки)

Акт 0 (открытие):

1. **Hero** — декларация «Мастермайнд, в который не попадают за деньги». Подзаголовок про закрытый клуб 8–10 мужчин. CTA `Условия входа ↓` (scroll к акту III). Ссылка `войти` — в хедере `(marketing)/layout.tsx` справа, а не внутри hero-блока.
2. **Зеркало** — два столбца: «Ты здесь, если» / «Ты НЕ сюда, если». Быстрый фильтр аудитории.

Акт I (Как мы живём):

3. **«Личный совет директоров»** — одна большая типографическая цитата, много воздуха, якорь позиционирования.
4. **Ритм года** — 4 карточки: 12 встреч в году · полугодовой выезд · годовой выезд с семьями · неделя как единица отчёта.
5. **«Один день в клубе»** — вертикальный таймлайн одного четверга из `/constitution` (синхра → отчёт за месяц → дополнительно → перерыв → разборы → обед → экскурсия → закрытие → after-party). Нарратив, не список.
6. **Бади** — отдельный маленький блок про ротацию 1:1 раз в месяц.
7. **Конфиденциальность как обещание** — ключевой блок под «можно снять маску». Жёсткая декларация + три пункта (NDA де-факто, голосование при исключении, правило про телефоны).

Переход-контраст:

8. **«Чтобы это не осталось разговорами — LUMM»** — крупный заголовок, подзаголовок «Встроенная система. Мы сделали её для себя, не на продажу.»

Акт II (Что под капотом):

9. **12-недельная цель (Wombo Combo)** — короткий текст про WOOP+HARD+12WY+SCI, скриншот мастера / карточки `/goal/my`.
10. **Еженедельный отчёт + AI-разбор** — скриншот Telegram-сообщения с триггером + карточки светофора.
11. **Финансы вслух** — скриншот ленты `/financials`.
12. **Штурвал** — короткий блок про фидбек через бота.
13. **Умный календарь** — пинг только отстающих. Маленький акцентный блок.
14. **Банк и штрафы** — таблица штрафов прямо на странице. Подпись «Штрафы — не репрессии. Это цена, которая делает выбор дорогим.»

Акт III (Вход):

15. **Как попасть** — пронумерованный список из 5 шагов (заявка → знакомство → голосование → тестовая → утверждение).
16. **Условия** — сухой список: 8–10 мест, Москва, взнос, банк на штрафы, обязательства по отчётам и присутствию.
17. **Окно приёма** — индикатор из env: «Свободных мест: N. Следующее окно приёма: <дата>.» Если `OPEN_SLOTS=0` — «Мы полны. Лист ожидания открыт.»
18. **FAQ** — 5–6 коротких вопросов в `<details>`/аккордеоне: почему только мужчины · что если пропущу · конфиденциальность · стоимость/куда идут деньги · что делает софт · удалённо нельзя.
19. **Финальный CTA** — «Если это твоё — ты знаешь, что написать.» Кнопка `Оставить заявку` → `href=NEXT_PUBLIC_APPLICATION_CONTACT` (ссылка в Telegram). Вторичная ссылка `Уже участник? → войти`.

Footer: логотип, год, контакт, ссылка `/login`. Без дополнительных страниц в MVP.

### Компоненты и взаимодействия

- Скролл к «Условия входа» по клику на hero-CTA — через `<a href="#about">` и `id="about"` на первой секции Акта I.
- FAQ — `<details>` (нативное разворачивание, без JS).
- Нет форм. Нет сайдбара. Нет UserMenu.
- Переливающаяся CTA — переиспользовать существующий `.btn-shimmer` из `src/app/globals.css`.

### Тестирование

- Юнит-тесты `src/lib/landing.ts`: парсинг `NEXT_PUBLIC_NEXT_WINDOW_DATE`, плюрализация «мест» (1 место, 2 места, 5 мест), fallback на «Мы полны» при `OPEN_SLOTS=0` или невалидном значении.
- Ручная визуальная проверка: hero на мобиле, таймлайн на мобиле, таблица штрафов не ломается в узком контейнере, скриншоты в блоках Акта II не расползаются.
- Проверка, что `/` публичен, `/dashboard` без auth редиректит на `/login`, логин не сломан.

## Open questions

- **Куда ведёт CTA «Оставить заявку»?** Телеграм админа кажется самым правильным на старте (нет БД, нет спама). Нужен конкретный `@username` перед билдом.
- **Нужны ли отзывы участников?** Я бы в MVP не добавлял — маленькая группа, отзывы из 3 человек выглядят хлипко. Вернёмся, когда будет 8+ участников.
- **Стоит ли показывать публично кусок конституции** (напр. кнопка «Прочитать конституцию полностью»)? С точки зрения exclusivity — конституция как документ клуба ценнее, когда она внутри. Предлагаю не выносить.
- **Логотип/бренд-вариант** — нужен ли отдельный лендинг-логотип или используем тот же, что в авторизованной части? Предлагаю тот же.
