# Member Profiles — Дизайн

Добавить "Мой профиль" (редактирование своих данных) и публичные страницы "Участники мастермайнда" (список + карточка каждого юзера). Минимальный набор полей — следим за PRD-приватностью.

## Scope

### Новые страницы
- `/profile` — свой профиль с редактированием
- `/members` — сетка карточек всех участников группы
- `/members/[id]` — публичная карточка конкретного участника

### Новые/изменённые API
- `GET /api/members` — **изменить** (сейчас возвращает всё, включая passwordHash) → отдавать только публичные поля
- `GET /api/members/[id]` — **изменить** по той же причине
- `PATCH /api/auth/profile` — **создать**, обновляет displayName + avatarColor текущего юзера
- `POST /api/auth/change-password` — **создать**, принимает `{currentPassword, newPassword}`

### Сайдбар
Добавить пункт **"Участники"** (иконка `◐`) между "Календарь" и "Бюджет". Рядом с названием — бейдж `NEW` (золотой фон, чёрный текст, `text-xs`). Бейдж статичный, хардкод в коде; уберём руками когда перестанет быть актуальным.

### UserMenu
В выпадашке по аватару — добавить первым пунктом **"Мой профиль"** (доступен всем, не только админам).

## Приватность

### Публичные поля (отдаются на `/api/members` и `/api/members/[id]`)
- `id`
- `displayName`
- `role`
- `status`
- `avatarColor`
- `avatarUrl` (если когда-то будет, сейчас nullable)
- `createdAt`

### Скрытые поля (НЕ возвращать в публичных эндпоинтах)
- `username` (логин)
- `passwordHash`
- `telegramId`
- `realName`
- `groupId` (тоже не надо утечкой наружу)

`/admin/members` использует отдельный admin-эндпоинт (`/api/admin/members`) и может видеть больше (например `username`, `status`) — так уже работает.

## Страницы

### `/profile` (свой профиль, Client Component)

**Layout:** обычный (в `(main)`, с Sidebar).

**Контент:**
1. Заголовок "Мой профиль"
2. Секция "Публичные данные" (карточка):
   - Превью аватара (большой кружок с первой буквой ника, цвет)
   - Input для displayName (мин. 2 символа)
   - Палитра цветов аватара (8 кружков, как в /onboard)
   - Кнопка "Сохранить" — PATCH `/api/auth/profile`
   - Сообщение об успехе/ошибке inline

3. Секция "Смена пароля" (карточка):
   - Input текущего пароля
   - Input нового пароля (мин. 6 символов)
   - Input подтверждения нового пароля
   - Кнопка "Изменить пароль" — POST `/api/auth/change-password`
   - Поля очищаются после успеха
   - Если у юзера `username === null` (редкий случай, напр. только Telegram) — секция прячется

### `/members` (список, Server Component)

**Layout:** обычный.

**Контент:**
1. Заголовок "Участники мастермайнда"
2. Подзаголовок с кол-вом активных
3. Grid карточек (`grid-cols-2 md:grid-cols-3 lg:grid-cols-4 gap-4`):
   - Карточка = ссылка на `/members/[id]`
   - Большой аватар (w-20 h-20)
   - Ник
   - Роль мелким текстом (`text-lumm-text-secondary`)
   - Hover: border lumm-gold

**Данные:** Server Component, прямой DB-запрос (фильтр по groupId текущего юзера, status = active).

### `/members/[id]` (карточка, Server Component)

**Layout:** обычный.

**Контент (центрированная карточка max-w-md):**
1. Кнопка "← Назад к участникам" (Link на `/members`)
2. Большая карточка:
   - Огромный аватар (w-32 h-32)
   - displayName (большой заголовок)
   - Роль (badge золотого цвета)
   - "Участник с DD.MM.YYYY" (маленьким текстом)

**Данные:** Server Component, прямой DB-запрос. Если member не найден или из другой группы — 404.

```
[Мой профиль]                  ← новое, всем
```

## API Детали

### `GET /api/members`

Возвращает массив публичных полей (см. выше). Фильтр: `groupId = currentUser.groupId`, `status = "active"`. Сортировка по `displayName ASC`.

### `GET /api/members/[id]`

Возвращает объект с публичными полями. Проверка: `groupId` совпадает с `currentUser.groupId`, иначе 404. Если `status !== "active"` — тоже 404 (неактивных не показываем).

### `PATCH /api/auth/profile`

Body: `{ displayName?: string, avatarColor?: string }`. Валидация:
- `displayName.trim().length >= 2`
- `avatarColor` — hex, matches `/^#[0-9a-fA-F]{6}$/`

Обновляет только переданные поля. Требует авторизации.

### `POST /api/auth/change-password`

Body: `{ currentPassword: string, newPassword: string }`. Валидация:
- `currentPassword` — bcrypt.compare с `members.passwordHash`, иначе 401
- `newPassword.length >= 6`

Если у юзера `username === null` (регался только через Telegram, хотя сейчас такой возможности нет — но на будущее) — 400 "У вашего аккаунта нет пароля".

## Что НЕ входит в scope

- Аналитика/графики на профиле (договорились минимум)
- Upload avatarUrl (остаётся nullable, колонка есть, UI нет)
- Редактирование realName, username, role, status в `/profile` (это админские штуки)
- "Видел/не видел" для бейджа NEW — статичный
- Тайм-аут сессии после смены пароля (оставляем текущую сессию живой)
