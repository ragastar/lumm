# Эпик 1: Цели + активация через бота — Дизайн

Первый эпик v0.1 БЕТА. Вводит понятие **личной цели** (бизнес + спортивная), которое в Эпике 2 станет якорем для LLM-сверки еженедельных отчётов. Плюс вводит **бот-активацию** — сообщение в групповой чат со ссылкой на профиль, чтобы все заполнили цели.

## Цели эпика

1. Участник может записать свою **бизнес-цель** и **спортивную цель** в `/profile`
2. Эти цели видны публично (в `/members` и `/members/[id]`)
3. Админ из `/admin/members` одной кнопкой запускает активацию — бот пишет в групповой чат с просьбой заполнить цели

## Решения (утверждены)

**Q1: Сферы Б/С/Л — Семья (не Спорт).** Цели (бизнес + спорт) и сферы отчётов (бизнес + семья + личное) — это **разные оси**. Schema отчётов не трогаем. Цели живут отдельными полями в `members`.

**Q2: Без персональных @mention.** Активация — общее сообщение в групповой чат без упоминания отдельных участников. Все видят текст + ссылку на `/profile`, кто не открывал — увидит при заходе в Telegram. Это упрощает эпик: не нужен `telegram_username`, не нужен admin-UI для редактирования.

## Scope

### Схема БД

`members`:
- **ADD** `business_goal TEXT` (nullable)
- **ADD** `sport_goal TEXT` (nullable)

Другие таблицы не трогаем.

### API

- `PATCH /api/auth/profile` — **расширить**: принимать `businessGoal`, `sportGoal` (строки или null, максимум 500 символов каждая, пустая строка → null).
- `GET /api/members` — **расширить публичный набор**: добавить `businessGoal`, `sportGoal`.
- `GET /api/members/[id]` — то же.
- `POST /api/admin/activate-goals` — **создать**: admin-only, отправляет фиксированное сообщение в `GROUP_CHAT_ID` через Telegram Bot API. Возвращает `{ ok: true }` или ошибку с текстом от Telegram.

### Модули

- `src/lib/telegram.ts` — **создать**. Чистая функция `sendGroupMessage({ chatId, text, parseMode? })`. Использует `fetch` к `https://api.telegram.org/bot<TOKEN>/sendMessage`. Не тянет grammy — это one-shot без polling. Нужна для Эпика 2 тоже, так что живёт в `lib/`, не в `bot/`.

### UI

- `/profile` (ProfileClient.tsx) — добавить секцию **«Мои цели»** с двумя `<textarea>` (Бизнес-цель, Спортивная цель), кнопка «Сохранить цели». Разместить после секции «Публичные данные».
- `/members` (grid, server component) — в каждой карточке под ролью добавить 1-2 строки с коротким превью: «Бизнес: …» / «Спорт: …» (обрезать до 80 символов с многоточием). Если цели нет — строку не показываем.
- `/members/[id]` (детальная, server component) — добавить секцию «Цели» под блоком с аватаром. Два пункта «Бизнес-цель» и «Спортивная цель», каждый в полном виде. Если пусто — показать «—» серым.
- `/admin/members` (MembersClient.tsx) — добавить кнопку в шапку **«Активировать цели»**. По клику: `confirm()` с превью текста → POST `/api/admin/activate-goals` → алерт «Сообщение отправлено» / ошибка.

### Текст сообщения активации

Хардкодим в обработчик. Финальный вариант:

```
Друзья, команда Level Up!

Время зафиксировать цели на этот сезон — бизнес и спорт.

Зайди в https://lumm.space/profile → «Мои цели».

Как заполнимся — двинем дальше по программе.
```

### ENV

- `TELEGRAM_BOT_TOKEN` — уже есть
- `GROUP_CHAT_ID` — уже есть (сохранили сегодня)

## Приватность

Цели — **публичные**, видны всем участникам группы (и только им). Групповой изолят сохраняется: `/api/members` фильтрует по `groupId` текущего юзера.

## Тестирование

### Unit (vitest)
- `src/lib/__tests__/telegram.test.ts` — замокать `fetch`, проверить:
  - правильный URL (`https://api.telegram.org/bot<TOKEN>/sendMessage`)
  - правильное тело (`chat_id`, `text`, optional `parse_mode`)
  - бросает ошибку при `ok: false` от Telegram
  - кидает ошибку если `TELEGRAM_BOT_TOKEN` не задан

### Manual smoke (чек-лист в плане)
1. Миграция применяется, колонки появились в `members`
2. PATCH profile с целями сохраняет, возвращает 200
3. На `/members/[id]` цели отображаются (из-под другого аккаунта)
4. На `/members` grid видно превью целей
5. Кнопка «Активировать цели» → в группе приходит сообщение с ссылкой

## Что не входит в эпик

- LLM-анализ отчётов (Эпик 2)
- Форма еженедельного отчёта в вебе (Эпик 2)
- Форма ежемесячного отчёта, поле «Капитал» (Эпик 3)
- Дашборды (Эпик 4)
- Запуск бота в polling-режиме (Эпик 2)
- Напоминания, cron, часовые пояса
- Персональные @mention участников
